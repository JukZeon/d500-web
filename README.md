# D500 Workbench

**BA7KTC / JukZeon 的 D500 网页信道工作台。**

站点：https://d500.example.com

为旧版、没有航空 AM 接收的即时通 D500 设计。文件在浏览器本地解析和编辑，不上传 DAT、工作表或方案内容。

## 功能

- 000–199 原生信道编号，可视化表格编辑、参数面板与频率分布图。
- 收发哑音分别选择关闭、模拟 CTCSS、数字 DCS；50 组 CTCSS、105 组 DCS 预设，支持手动填写与 N/I 极性。
- V1 高/低功率、带宽、繁忙禁发、扫描添加、PTT-ID、信令码组、可选信令、静音方式与扰频编辑。
- 38 项整机设置和 A/B/C/D 频率区的 7 项参数，随 DAT 导出；显示修改数量，可恢复模板值。
- 搜索、频段筛选、分组、备注、多选批量编辑、复制、移动编号、删除和撤销/重做。
- 导入旧版原厂 DAT，修改后导出；保留未编辑区域、未知标志位与原始 GBK 名称编码。
- 无修改导出与原文件逐字节一致；有修改时仅重写明确编辑的字段。
- XLSX、CSV、TSV 导入；XLSX、CSV 和空白模板导出；收发亚音拆分为类型、模拟频率、数字码列，兼容既有 K5Web 工作表。
- 浏览器自动保存、完整 `.d500.json` 方案备份与恢复。
- Web Serial 连接写频线、实验性读机、读取进度、本机原始备份、DAT 转换及通信记录；写入差异预览。直接写入入口待实机验证后开放。
- 响应式桌面/手机布局；所有字体、脚本和样式随站点托管。

## 使用

1. 用 **D500 V1 原厂写频软件**读取机器，并保存原始 DAT 备份。
2. 在网页中导入 DAT，确认预览后替换列表；也可只载入模板。
3. 直接编辑信道表，或点选行在右侧编辑参数；高级信令位于折叠面板。“电台设置”编辑已确认的整机参数。
4. Excel 导入可替换列表或按原生编号合并，同编号以导入内容为准。表格未提供的带宽等字段沿用现有同编号信道。
5. 导出 DAT，在原厂软件中打开、核对后写入电台。

新建空白方案可直接导出表格或方案备份；导出 DAT 需要先载入本机原始 DAT 模板。项目没有使用 K1toD500 的 V2 默认配置替代 V1 设置。

### 浏览器连接（v0.3.0-beta.1）

电脑 Chrome / Edge 打开 HTTPS 站点，在“连接电台”中选择本机写频线，确认是旧版 D500 后点击“读取电台”。没有自动连接或后台扫描。读取完成先保存浏览器本机备份，再通过“载入工作台”选择替换、合并或只载入模板；可下载 DAT、原始配置备份和通信记录。

该功能依据固定版本原厂 CPS 的静态分析实现，**尚未实机验证**。读取范围是配置区 `0x0000–0x31FF`，不是全芯片或固件备份；未知响应、密码保护、地址不匹配、超时或断开会停止。生产页面的写入按钮固定禁用，仅提供差异预览，仍可导出 DAT 交给原厂软件写入。候选写入实现和测试留在源码中，等待真实电台补齐协议证据。详见[串口协议研究](docs/SERIAL_PROTOCOL.md)。

### 格式约定

- D500 原生编号：0–199，界面显示为 000–199。
- K5Web `#` 编号：1–199 保持不变，200 映射到 D500 的 000。
- 频率单位 MHz，最多 5 位小数（10 Hz）。发射频率留空使用 DAT 的全 FF 编码表示接收专用；新增此类配置仍需原厂软件核对。
- 亚音留空表示关闭；模拟亚音示例 `88.5`；数字亚音示例 `D023N` / `D023I`。
- 已验证的 V1 原厂软件保存逻辑仅复制 8 个 GBK 字节（常用汉字 4 个 / 英数字 8 个）；新增或更名按此限制校验。DAT 名称记录虽然分配 16 字节，并不代表原厂软件能完整保存 8 个汉字。导入的原始长名称未修改时保留，不自动截断。详见[名称验证](docs/DAT_FORMAT.md#名称长度的实际验证)。
- 出厂文件中的非标准亚音用 `RAW:<原值>` 保留。
- 分组、备注仅保存在网页方案和表格中，不写入 DAT。
- 导出表格不添加 BA7KTC 个人署名。

## 兼容与验证边界

基础 DAT 布局移植自 [Liuli-Lumine/K1toD500](https://github.com/Liuli-Lumine/K1toD500)，修订 `e65cbb309986f0f37babaae7fac77f9fd21b5ab1`。v0.2.0 对官方 V1 CPS 进行了静态分析，修正上游 V2 的三档功率假设，增加信令位及整机配置映射，提供可重复执行的元数据检查和名称机器码验证脚本，见[格式研究](docs/DAT_FORMAT.md)。

已用 BA7KTC 提供的旧版 `KTC.dat`（113 条有效信道）与 `出厂值参考.dat`（8 条有效信道）验证 1025 行格式、GBK 解析、无修改逐字节往返和单字段修改。个人原始文件留在被忽略的本地 `.deploy/private-fixtures/` 中，不进入 Git、源码下载或部署包。

v0.3.0-beta.1 新增实验性串口读取和候选写入协议。模拟测试与文件往返验证不等于实机读写验证；直接写入尚未开放，不支持固件升级。原厂 DAT 流程继续可用。

## 开发

Node.js 22.12+：

```sh
npm ci
npm test
npm run build
npm run dev
```

React + TypeScript + Vite；SheetJS CE 0.20.3 使用官方分发包固定在 `vendor/`，不依赖过期的 npm 同名包版本。`package-lock.json` 固定依赖。

公开测试涵盖 DAT 布局验证、BCD、亚音、GBK、名称兼容限制、位掩码、38 项菜单与 28 项 VFO 参数精确写入、未知字节保留、复制、删除、XLSX 往返、K5 编号映射、旧草稿迁移和项目校验。本地存在私有夹具时另运行对应回归测试。

串口测试使用模拟响应，覆盖分片读取、超时/取消/断开、200 块配置读取、未知帧拒绝、差异冲突、候选写入的备份与回读失败处理；不使用或扫描真实串口。协议证据提取脚本只读分析原厂二进制，不随网站执行。

## 部署与回退

详见 [部署说明](docs/DEPLOYMENT.md)。站点使用独立的只读静态容器，通过已有 Docker `proxy` 网络接入 Nginx Proxy Manager，不直接暴露容器端口。

```sh
# 先完成提交，再部署；使用本机已有 SSH 配置。
bash scripts/deploy.sh
```

每次发布生成对应版本的 `source.zip`、`LICENSE.txt` 和 `version.json`。源码下载排除本地研究二进制和个人测试文件。
