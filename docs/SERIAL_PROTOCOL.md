## 当前通信顺序

只保留一套当前实测可读的握手，不提供旧协议选择器。

- 串口：9600 / 8N1，无流控；DTR=1、RTS=0、Break=0。关闭时清除 DTR。
- 握手前先清理启动数据：最少等待 500 ms，且接收静默 250 ms 后才发送 HELLO；最多等待 3 秒，持续异常数据则停止。清理仅发生在首个请求之前，不跳过通信过程中的未知帧。
- 原厂发送字节约间隔 16–48 ms，网页使用 32 ms。
- 握手：`55 20 25 07 06 FF DC 02`。
- 返回：可带 `06`，随后 49 字节识别帧，末字节 `55`。本机固件识别文字为 `VC905410`，不作为全系列兼容声明。
- 主机 `06`，再读密码状态 `53 3D F0 10`。
- 已观察无密码状态为 12 个零、`01 00 00 10`。另保留原厂 V1 空格密码的明确判断；其他状态停止，不猜测密码。
- 读命令：`53 地址高 地址低 长度`；返回 `58 地址高 地址低 长度 数据`，可有单个前导 ACK。核对地址与长度。
- 每次读完发送 `06`，它的回复 ACK 可能留待下一次读取处理。只在密码边界容许本机出现的单个 `05`；不任意丢弃未知帧。
- 写会话先完成握手及密码读取，消费密码确认的 `06`；第一块发送 `58 地址高 地址低 10 数据[16]`，等候 `06`；后续每块前先发主机 `06`，再发送 `58` 帧、等候 `06`。
- 抓包中的第一块配置写入尾部有一个额外 `00`，信道写入没有；网页不复制这个尚无解释的额外字节。

旧官网 V1 静态二进制中发现的握手曾导致本机零响应，已从运行路径移除。历史提取脚本与旧哈希仍用于研究，不是网页选项。

## 写入事务与恢复

1. 连接与读取分开。连接只完成识别及密码状态检查，不读取信道或整机配置。载入 DAT 或完整方案后即可“写入方案”；也可直接写入时选择端口。没有强制预览或勾选确认。
2. 所选范围有设备基准时，比较方案目标与设备状态，只发送差异；未建立基准的范围，发送文件中的完整已支持块。已确认写入的范围可作为后续增量基准。修改一部分范围后，不会把另一范围错误地标记为已知。
3. 实际读取的基准会持久化保存；从未读取时不伪造原始备份。ACK 推算状态不会保存为读机备份。
4. 新开一个独立写会话，核对识别帧，按捕获顺序写入白名单差异块，每块等待设备 ACK。
5. 所有写块确认后关闭会话，显示“写入完成”。不自动进行写后回读；需要核对时手动读取。按已确认写入更新下一次差异计算的基准，保留另一范围尚未写入的编辑。

增量写入以 16 字节为单位。无基准时无法知道电台与文件的差异，因此按方案覆盖所选范围：信道及名称 400 块（含空槽位清除），已支持设置 13 块；全部最多 413 块。不写额外的第 200 条记录、额外名称、密码、固件或其他配置块。设置块内未映射字段沿用文件原值，不假称已保留电台当前值。

完成后的 `source: write-ack` 表示收到设备确认后的预期状态，不表示已回读；`knownScopes` 记录实际写入的信道 / 设置范围，未知范围仍按文件写入，已知范围继续增量。备份库拒绝保存推算状态。手动读取得到的真实数据会作为新备份保存。

串口会话分开可避免把读取残留 ACK 当成写入成功。每次关闭时清除 DTR，并保留 2,500 ms 的退出间隔后才释放端口，下一会话仍须等待启动数据清理完成。没有引入未捕获的读写交替流程。每块开始写入后完成整帧，取消在块与块之间生效。ACK、备份或通信异常均停止；没有自动重试或自动回滚。中断可能已经写入部分内容，需重新读取。

## 2026-10-28 连续会话故障

现场浏览器记录显示，新端口打开时已有残留识别帧及 `Uart functional API interrupt example` 启动文字；旧实现直接交给握手解析，导致识别格式错误。另在 Mac 上复现了：第一次完整读取成功，退出 500 ms 后紧接第二次握手，返回 `55` 加同一启动文字而非识别帧。启动文字属于设备重启输出，不能作为有效握手或 ACK。

实测把退出间隔延长到 2,500 ms 后，连续三个独立的“识别、密码状态检查、读取首块、退出”会话均成功。该结果支持修正会话退出等待，不代表重复发送握手即可恢复；一次识别到启动文字后直接重发 HELLO 的实验仍超时，运行实现没有加入此类重试。

本轮诊断先完整备份 12,800 字节，哈希与先前 Mac 备份一致。公开文档不附个人配置和原始通信内容。

beta.3 修复后在 Chrome 中完成“读取 → 写前检查 → 3 块增量写入 → 全区回读”，共 600 个读取块、3 个写入块，所有写块 ACK 正常。总共仅 3 字节变化，其余 12,797 字节与原始备份一致。随后独立读取确认测试值，恢复原来的三个块并回读确认。见[实测审计](browser-write-audit.json)。未操作物理发射键或刻意断电。beta.4 保留相同的写帧与 ACK 时序，按用户要求移除自动写前整机读取和写后回读。

增量编辑限于信道、名称、已确认菜单、VFO 字段及开机文字；文件直写限于上述 413 个块，不发送密码、校准、型号、频段限制等区域的写命令。读机备份范围为配置区，**不是固件或全 EEPROM 备份**；DAT 未读到的第 800–1024 行为 FF 占位。
