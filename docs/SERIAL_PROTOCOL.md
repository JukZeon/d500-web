# D500 V1 浏览器读写研究

BA7KTC / JukZeon，2026-10-27。v0.3.0-beta.1。

## 当前状态

网页提供 Web Serial 连接、实验性读取、本机原始备份、DAT 转换、写入差异预览和通信记录下载。**尚未连接真实电台验证协议。生产界面的写入按钮固定禁用，无写入事件处理器。** `writeCandidate` 是待验证的协议实现，仅由模拟测试调用；不能把它或测试通过解释为实机读写成功。

直接连接在用户点击后调用 `navigator.serial.requestPort()`，由用户选择写频线。不开启自动连接、不扫描本机串口、不切换 DTR/RTS、不上传数据。读完、取消、异常后关闭串口；拔线时更新状态。现有文件编辑功能不依赖串口。

浏览器需提供 Web Serial，并运行在安全上下文。优先使用电脑 Chrome / Edge；实际以能力检测为准。站点 HTTPS 和 `Permissions-Policy: serial=(self)` 允许本站请求串口，浏览器仍需单独授权。参考 [Chrome 官方文档](https://developer.chrome.com/docs/capabilities/serial) 和 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Web_Serial_API)。

## 分析对象和可重现证据

与 [DAT 研究](DAT_FORMAT.md) 使用同一个官方 V1 CPS，SHA-256：

```text
c2d7e2d42a78d949b03d7557b0785139a856485d20c0cb12e9ae43979a3c3559
```

下表是固定二进制中看到的常量/赋值，地址为 PE 虚拟地址。完整二进制、个人数据和反汇编不随项目分发。

| 项目 | 原生位置 | 观察 |
| --- | --- | --- |
| 串口参数 | BSTR `0x426b6c`，设置函数 `0x548250` | `9600,N,8,1`，二进制输入 |
| 握手数组 | `0x465201`–`0x46527d` | `55 20 21 01 23 FF DC 02` |
| 握手响应判断 | `0x54c0a1`–`0x54c0ea` | 前导 `06` + 49 字节，或首字节 `01` 的 49 字节；末字节 `55` |
| 频段识别 | `0x54c2e8` 起 | 0–5、16–21 字节按三位十进制频段上下限解释 |
| 首个读取请求 | `0x54d2ee`–`0x54d338` | `53 3D F0 10` |
| 密码检查 | `0x54d5da`–`0x54da74` | 复制上述 16 字节，检查 ASCII 空格和密码输入值 |
| 配置读取 | `0x54b83b`–`0x54b9bf` | `53 地址高 地址低 40`；地址每块加 64 |
| 读取返回头 | `0x54e43c`–`0x54e527` | 在帧开头搜索 `58`，数据起点为标记位置 + 4 |
| 收到数据后确认 | `0x54b457`–`0x54b4b1` | 主机发送 `06` |
| 第一块写入 | `0x5547bb`–`0x554966` | `58 地址高 地址低 10 数据[16]`，总长 20 |
| 后续写入与确认 | `0x55190e`–`0x551bda`、`0x550ed0` 起 | 每块 16 字节，收到 `06` 后推进 |

运行只读提取脚本会核对二进制哈希，并提取握手常量与串口字符串：

```sh
python scripts/inspect-cps-protocol.py /path/to/D500_vip_CPS.exe -o /tmp/protocol-evidence.json
```

依赖 `pefile`、`capstone`，与已有研究脚本相同。脚本不执行或修改 EXE。自动结果见 [cps-protocol-evidence.json](cps-protocol-evidence.json)。帧时序、ACK 前缀和地址校验策略仍是基于静态分析的候选实现，不是抓包结论。

## 本版候选实现

1. 以 9600 / 8N1 打开用户选择的串口，逐字节发送握手，字节间暂定约 1 ms。
2. 核对识别帧结构与频段数字；这不构成独立的 V1/V2 型号鉴定，页面还要求用户确认无航空接收版本。
3. 发送 ACK，再读取 `0x3DF0` 的 16 字节。前 6 字节必须是 ASCII 空格，否则停止并提示使用原厂软件；不猜测或绕过密码。
4. 分 200 块读取配置区 `0x0000–0x31FF`，每块 64 字节。响应按 `58 地址高 地址低 长度 数据` 解析，容许一个 `06` 前缀；地址/长度不符、未知字节、超时或取消立即停止，不盲目重试或继续扫帧。
5. 原始配置和识别帧先写入浏览器 IndexedDB；再按 DAT 解析。解析失败仍保留原始备份供排障；未完成的读取只留下通信记录，不替换工作台。
6. 读机 DAT 的第 800–1024 行为 FF 占位。界面明确标出读取范围，**该备份不等于全 EEPROM、校准区或固件备份**。两份已有私人 DAT 在行 800 以后全为 FF，但这不能证明所有设备都如此。

未确定：真实写频线对字节间隔的要求，响应中额外字节的完整规则，编程模式退出要求，不同固件的识别差异，以及电台在写入后何时持久化。这些必须用实机日志补齐。没有依据实现固件升级或校准区操作。

## 写入边界

预览将“DAT 原模板 → 当前方案”的差异应用到本次读取数据；没有变化的设备字节保留。原模板与设备在同一待改字段发生冲突时拒绝预览，要求重新读取并合并。

只允许信道 0–199、名称 256–455、38 项菜单和 28 项 VFO 白名单字段的变更。不把导入文件的整片内容覆盖回机器，不写密码、型号、频段限制、校准和未知区域。当前预览按 16 字节分块统计，设置数量表示数据块，不表示菜单项数。频率和哑音按完整字段比较，标志位按各自掩码比较，避免逐字节拼出一个未指定的频率。

候选写入路径先重新读取配置，逐块与预览基线比较；等待原始备份保存成功后，才发送第一个 `58` 命令。每块要求 ACK，并再次读取逐字节核对；ACK 或回读失败立即停止，不重试、不声称回滚成功。多块写入不是原子操作，中断后可能已有部分块落盘，必须重新读取检查。

## 验证和下一步

`npm test` 中的协议模拟器验证帧组装、200 块读取、身份/地址/密码拒绝、DAT 转换、差异冲突、写前重新读取和备份、ACK/回读失败停止。串口流测试覆盖分片、余留数据、取消、超时、断开和锁释放。模拟器按候选协议构造响应，**不能反过来证明真实协议正确**。

待用户接好旧版 D500 后：

1. 只读取，保存原始结果和通信记录。
2. 与同机原厂 CPS 导出的 DAT 核对，验证地址、长度和未知区域。
3. 在明确选定的一条测试信道上验证最小写入及回读，再用原厂软件交叉核对，并验证断电重启后的保存结果。
4. 有实机证据后再开放生产写入入口，记录测试机器/固件及证据范围。
