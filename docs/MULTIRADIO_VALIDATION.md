# 多型号验证记录

日期：2026-10-29。以下按版本保留验证过程；最新结果见 0.6.0-beta.4。

## 架构与来源

新增型号通过内置驱动 Worker 和 Web Serial 直接访问写频线，不运行本机服务。CHIRP 固定提交、许可、文件哈希及参考镜像哈希见 [UPSTREAM.json](../radio-core/vendor/UPSTREAM.json)。LOSEHU 基本设置对应的固件源码提交见 [驱动说明](../radio-core/README.md)。

## 0.5.0-beta.1 已验证

- 108 项 TypeScript 测试通过，覆盖既有 D500 功能、型号隔离、1000 信道表格导入、空发射频率、独立 CTCSS / DCS、编号与字符检查，以及浏览器串口碎片拼接、部分读取、超时、断线和整帧发送。
- 17 项 Python 测试通过：四种公开参考镜像的原始字节无变化往返；收发频率与跨类型哑音；仅接收；中文名称；型号不匹配与裸镜像拒绝；设置变更；LOSEHU 写入边界及掩码位保留。
- UV-5RH 缺少上游同型号参考镜像，使用同一父类布局构造并正确标记型号的测试镜像，验证 1–1000、功率与频率编码。此项不能替代本型号实机验证。
- 同一编解码在 Pyodide WASM 下完成 UV-5R、泉盛原厂、LOSEHU、Egzumer 的往返；浏览器串口适配入口的读写、驱动使用的 sleep 接口通过运行时验证。
- 浏览器实际操作：无本机连接器运行时导入 LOSEHU 256 KB 参考 IMG、修改中文名称、独立模拟／数字哑音和基本设置、导出 IMG。独立解码确认收发频率、DCS 反码和 CTCSS 正确；仅 18 个字节变化，均位于选中信道记录、对应名称和静噪字节，其余区域（包括全部高地址扩容数据）保持原样。
- 浏览器检查 UV-5R 的 0–127 与设置分组、UV-5RH 的 1–1000 与 VFO 设置、LOSEHU 的 256 KiB 信息、基本设置和下拉选项；窄屏页面可使用。
- TypeScript 严格检查和生产构建通过。

## 0.5.0-beta.1 时尚未验证

新增型号没有在本项目逐台进行实机读取、写入、断电重启后核对或跨硬件批次验收。现有 D500 的实机记录不作为这些型号的证明。不能把软件测试通过表述为“所有型号已可安全刷入”。

LOSEHU 只对已匹配版本开放已核对的基本设置；侧键、信令、卫星数据、字库、多系统引导等不在编辑范围内。未知版本停止操作。不同硬件和同名衍生型号不自动视为兼容。

配置写入沿用各 CHIRP 驱动规定的范围；新增型号目前没有独立实现硬件增量上传，也不执行额外的写前整机读取或写后自动回读。

## 0.5.0-beta.3：UV-5RH 通信修复

2026-10-29：在 Chrome 中复现普通 UV-5RH 读取只出现 RX、未发出握手就报告 `Unexpected error communicating with the radio`。完整异常链显示浏览器 `TextDecoder` 拒绝 `SharedArrayBuffer` 支持的视图；Node 的同名接口接受该视图，先前 Node WASM 测试未覆盖此差异。Worker 改为复制到普通缓冲区后解码，各内置驱动共用此修复。

- `npm test`：109 项 TypeScript 测试、8 项 Node 测试通过。其中 4 项新增测试模拟浏览器解码限制，覆盖初始残留数据、写入确认、中文错误、缓冲长度和超时；另验证完整异常链及会话信息写入通信记录。
- 17 项 Python 测试、四种参考镜像的 WASM 编解码测试、严格类型检查和生产构建通过。
- 实际 Chrome + 生产 Worker + Pyodide，连接模拟串口端点完成三次握手和 3,183 次共享缓冲 RPC：读取 526 块（33,664 字节）、解析 78 条参考信道和 79 项设置，修改一个信道和一个设置，写入 526 块并逐块确认，测试端主动再次读取后整份镜像一致。每次握手均注入用户报告的 18 字节初始数据。参考内容来自公开 UV-17Pro 布局，仅作模拟；测试回读不改变平台默认不自动回读的行为。
- 本机通过 USB 写频线，按同一普通 UV-5RH 驱动和 115200 8N1 实际读取成功：33,664 字节、13 条信道、3 组配置。原始 IMG、配置与通信记录仅保存在本机，没有写入电台或公开原始内容。

本轮实机读取使用本机串口；浏览器的 Web Serial + Worker 链路通过模拟端点验证。两项结果不能合并表述为网页实机读写全部通过；网页实机读取、实机写入及断电核对仍待验收。

## 0.6.0-beta.2：中文与连续会话实测

- 普通 UV-5RH 实际读取 33,664 字节、134 条信道，名称原始字节确认是 GBK。修复旧驱动按单字节字符串解码的问题；12 字节限制同时用于前端、共享库和底层编码。
- 原始 134 条信道全部重新编码，镜像零字节变化。名称或频率修改保留未修改字段、隐藏位和保留字节。
- 实机临时空位写入 6 个汉字“中文名称测试”，跨串口会话读回字节一致。隔离测试发现全 FF 单块写入不能可靠清空记录，因此未加入增量上传；随后完整写回原镜像，526 块确认。独立读取全部字节一致、134 条原信道和空测试位置恢复。
- Chrome + Web Serial + 生产 Worker + Pyodide 从这台电台实际读出 134 条信道，中文名称正确；浏览器下载的原始 IMG 同已恢复镜像逐字节一致。
- 回归覆盖 139 项 TypeScript、8 项 Node、26 项 Python 测试；四种参考镜像与普通 UV-5RH GBK 合成镜像的 WASM 测试。检查超长名称拒绝、未改字节保留、连续读写会话、错误地址帧拒绝及缺少 ACK 时立即停止。
- 逐型号核对了独立网页写频、EEPROM 工具与固件项目，详见 [MODEL_RESEARCH.md](MODEL_RESEARCH.md)。LOSEHU 补充 13 字节名称校验；不把容量或早期字库映射当成通用布局。

脱敏实测摘要见 [uv5rh-hardware.json](audit/uv5rh-hardware.json)。未公开个人镜像或原始通信记录。实机测试包含独立回读验证，平台日常写入仍不自动回读；没有添加写前整机读取。UV-5RH 的物理断电持久化、整机设置逐项核验及其他手台的实机验收仍未完成。

## 0.6.0-beta.3：共享库中文名称路径

- 未打开的目标方案不再沿用旧草稿中的英文字符限制；只更新应用预览的名称能力，保留设备频段及 IMG 尚待重新解码的标记。
- 默认使用可编码的完整原名，旧英文别名不再优先覆盖中文；超过字节上限才退回已有机型别名。显式选择别名与逐条改名保持可用。
- 141 项 TypeScript、8 项 Node 测试通过，新增旧字符缓存、中文原名与别名优先级、12 字节边界的回归用例。
- Chrome 实际完成“D500 示例 → 共享信道库 → 未打开的 UV-5RH 方案”应用；先存英文别名，再次应用默认恢复中文，别名选择仍可取回旧名称。6 条中文／中英混排信道进入方案，切换机型后名称一致。本轮仅修改网页方案，未写入实机。

## 0.6.0-beta.4：表格参数与台站识别

- 146 项 TypeScript、8 项 Node 测试通过；回归覆盖不连续编号、AM 仅接收、扫描添加与无效扫描值、同频异站保留及重复导入。
