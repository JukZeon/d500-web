# D500 DAT 格式研究

2026-10-28，BA7KTC / JukZeon，Workbench v0.4.0-beta.1。

## 证据与边界

基础结构衍生自 [K1toD500](https://github.com/Liuli-Lumine/K1toD500)。随后分析了两个固定原厂 CPS 二进制的 VB6 控件与保存函数：

| 对象 | SHA-256 | 用途 |
| --- | --- | --- |
| 官网 V1，2024 | `c2d7e2d42a78d949b03d7557b0785139a856485d20c0cb12e9ae43979a3c3559` | 信道、名称保存路径及初始菜单研究 |
| 用户云电脑实际使用的 CPS，2025 | `dfc9f53d9994e54cd097d3bcd617b118bfdfd596ce94a34289c257ce73430ce3` | 实际读写抓包、当前菜单和 VFO 映射 |

`scripts/inspect-cps.py` 核对这两个哈希，并提取各自 29 个 VB6 对象的元数据；`MENU_SETTINGS` 和 `VFO_SETTINGS` 的原生地址现指向 2025 二进制。原厂程序、完整反汇编和个人文件不分发。程序文件名、软件版本名称不能据此推定电台硬件代际；网站不提供航空版固件刷写。

## 文件结构

1025 个非空行，每行 19 个十进制整数：

```text
floor(row / 16)  row % 16  row  byte0 ... byte15
```

前三项是地址元数据，余下 16 项为数据字节。数据行对应设备地址 `row × 16`。

| 行号（从 0 开始） | 内容 | 处理 |
| --- | --- | --- |
| 0–199 | 200 条信道 | 已确认字段可编辑 |
| 200–223 | 额外/保留记录 | 保留 |
| 224–227 | 整机菜单索引 | 42 项白名单可编辑 |
| 237–239 | ANI / 按下发码 / 松开发码 | 保留，当前不做信令内容编辑 |
| 240/242/244/246 | A/B/C/D 频点与频差 | 已确认字段可编辑 |
| 241/243/245/247 | A/B/C/D 模式参数 | 已确认字段可编辑 |
| 251 | 开机文字 | 可打印 ASCII，最多 15 字符 |
| 256–455 | 对应信道名称 | GBK，记录占 16 字节 |
| 其他 | 信令、FM、保留等 | 保留 |

浏览器读机只取得 `0x0000–0x31FF`。生成 DAT 时未读取的第 800–1024 行为 FF 占位；不能把它称为固件或完整 EEPROM 备份。其他来源 DAT 超出读取区的数据仍随模板保存。

## 信道数据

| 字节 / 位 | 内容 | 编码 |
| --- | --- | --- |
| 0–3 | 接收频率 | 小端压缩 BCD，MHz × 100000 |
| 4–7 | 发射频率 | 同上，全 FF 表示仅接收 |
| 8–9 | 接收哑音 | uint16 LE |
| 10–11 | 发射哑音 | uint16 LE |
| 12 低 4 位 | 信令码组 | 0–14 显示为 1–15 |
| 13 低 4 位 | 可选信令 | 0 关 / 1 DTMF / 2 2TONE / 3 5TONE |
| 13 高 4 位 | 静音关系 | 0 QT / 1 AND / 2 OR |
| 14 低 2 位 | 功率 | 0 高 / 1 低；陌生枚举保留 |
| 14 bit 4 | 扰频 | 0 关 / 1 开 |
| 15 低 2 位 | PTT-ID | 0 关 / 1 BOT / 2 EOT / 3 BOTH |
| 15 bit 2 | 扫描添加 | 0 否 / 1 是 |
| 15 bit 3 | 繁忙禁发 | 0 关 / 1 开 |
| 15 bit 6 | 带宽 | 0 宽 / 1 窄 |

全 FF 信道为空。仅修改明确字段的掩码，其他位保持原样；复制或移动沿用原记录。解析失败不会默默删除该信道。

### 哑音

0 为关闭；1–105 为标准 DCS 正码，106–210 为同序反码；CTCSS 为 Hz × 10，例如 88.5 → 885。不能解释的值显示 `RAW:<值>` 并保留。网页区分模拟 CTCSS 与数字 DCS，DCS 的编码和 N/I 极性独立选择。DCS 不等于 DMR 通信模式。

## 名称长度的实际验证

2024 官方 V1 保存函数先检查字符长度，再转换 ANSI/GBK 数组，实际仅复制前 8 字节并处理双字节边界：检查位置 `0x48bd1d`、转换 `0x48c2b3`、限制数组上界为 7 的位置 `0x48c34c–0x48c38b`。

在 Unicorn x86 模拟器中执行该段原厂机器码，最小替身提供 VB6 整数/循环帮助函数：4 个常用汉字完整保存，5 个及 8 个截为 4 个，ASCII 保留前 8 个，中英混合遇半字边界丢弃不完整字节。见 [7 组原始结果](cps-name-verification.json)。

上述结果仅验证固定原厂软件的保存路径，不代表电台存储或屏幕限制。

2026-10-28，在同一台旧版无航空接收 D500 的 001–005 信道上，分别写入 5、6、7、8 个常用汉字及 16 个英数字。名称逐字节回读一致，各信道参数未变。操作者查看电台屏幕，确认完整显示 6 个汉字或 8 个英数字，超过 6 个汉字显示「.」。中英混排的具体显示宽度尚未独立验证。测试后五个原名称已恢复并再次回读一致。见[实机审计](channel-name-hardware-audit.json)。

网页新增和更名现采用实测的 16 GBK 字节存储上限，提示屏幕显示范围，不自动截断；不支持 GBK 或超出 16 字节时报错。2024 CPS 的历史保存路径复现：

```sh
python scripts/verify-cps-names.py D500_vip_CPS.exe -o name-results.json
```

## 整机菜单

菜单索引 `i` 对应行 `224 + floor(i / 16)`、字节 `i % 16`，保存 ComboBox 的零基 ListIndex。当前映射依据 2025 CPS 初始化与 Click 保存函数。

| 索引 | 内容 |
| --- | --- |
| 0 / 2 / 5 / 7 / 8 / 9 | TDR、SQL、TOT、自动锁键、语言、操作提示音 |
| 14 / 15 / 16 / 17 | DTMF 侧音、繁忙禁发、扫描添加、扫描方式 |
| 20 / 21 / 23 / 24 / 25 | PTT-ID、延迟、报警方式、报警信道、有效信令提示 |
| 27 / 28 / 30 / 31 | A/B 显示、VOX、加发身份码 |
| 32–39 | 状态栏、A、B、电压、信号、菜单、发射、接收颜色 |
| 45 / 46 / 47 / 48 | ANI 长度、中继激活音、自动关机、双守返回 |
| 49 / 50 / 51 / 52 | 尾音消除、过中继消尾音、信道同步显示、手咪增益 |
| 54 / 55 / 56 / 57 | 扬声器、手咪接口、蓝牙适配器、自动背光 |
| 58 / 59 / 61 | 按下发送提示音、松开发送提示音、遥晕遥毙开关 |

修正了旧映射中把 31 写成 VOX 延迟、51 写成中继延迟、52 写成 DTMF 增益、56 写成面板类型的错误。

自动背光的 ListIndex 为 0–250：Form_Load `0x4bb435–0x4bb59f` 添加关闭和 1–250 档。提示音 58/59 为关闭、开启、开启 + 本机响。没有独立单位证据的数值档位不擅自添加秒数单位。

索引 60 初始化为“加电按键开机”，但该二进制的 Click 路径未正确引用索引全局变量，已找到的读机映射亦未引用它；不能仅凭相邻索引猜测其电台语义。本版保留原值，不开放这个开关。密码、校准和频段限制也不做推测性编辑。

## 频率模式 A/B/C/D

| 频点行字节 | 内容 | 编码 |
| --- | --- | --- |
| 0–7 | 当前频率 | 8 个十进制数字字节，MHz × 100000；不是 BCD |
| 8–13 | 频差大小 | 6 个十进制数字字节，MHz × 1000；原厂写第 8 字节为 0，编辑范围 0–99.999 MHz |
| 14–15 | 未确认 | 保留 |

| 参数行字节 | 内容 |
| --- | --- |
| 0–1 / 2–3 | 接收 / 发射哑音，uint16 LE，编码与信道相同 |
| 4 / 5 / 6 | 信令码组、静音关系、可选信令 |
| 7 / 8 / 9 | 扰频、带宽、功率 |
| 10 / 11 | 频差方向、步进 |
| 12–15 | 保留 |

A/B 为主要编辑区，C/D 在网页中作为可展开的备用数据区展示，不据此宣称机器有四个同时显示的操作区。

开机文字行为 251，先以 ASCII 空格清空 16 字节再写字符。原厂 KeyPress 在输入前限制当前长度不大于 14，网页上限采用 15 个可打印 ASCII 字符；未编辑的陌生原始内容保持原样。

## 写入和项目兼容

默认只写所选范围的修改块：已知块与上次读写状态比较，未知部分与载入文件比较。完整覆盖需单独选择“完整写入”。每块收到设备 ACK 后继续，不自动增加写前整机读取或写后回读。更新写入基准时保留其余未写入的修改和文件中超过读机范围的数据。写入流程见[串口协议](SERIAL_PROTOCOL.md)。

旧方案新增字段从原 DAT 继承。表格缺少带宽、扫描、信令等字段时沿用当前同编号信道；不把旧表里的同名但不同义列或 DMR 模式强行映射到模拟 D500。
